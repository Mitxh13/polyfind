# S6-05 — Final acceptance, clean-room setup, and viva preparation

## Module
`release`

## What to build
Perform a clean setup and verify every PRD success criterion.

## Acceptance criteria
- [ ] A team member who did not implement the setup follows the README successfully.
- [ ] Acceptance checklist maps PRD criteria to test/report evidence.
- [ ] Known limitations and fallback behavior are documented.
- [ ] Final demo and viva notes explain design, baselines, metrics, and research limits.

## Dependencies
Complete the preceding slice(s) needed for this module and review `docs/ARCHITECTURE.md` plus the relevant sprint plan.

## Mockup / reference
Not applicable unless the implementation adds a UI surface.

## Out of scope for this slice
Do not add new features during final acceptance unless a blocker requires it.

## Human review required?
Yes if the implementation touches secrets, infrastructure, authentication, destructive migrations, or changes a documented freshness guarantee; otherwise normal PR review.

## Ownership
Shared; assign one driver before work begins.

## Evidence to attach to PR
- Acceptance criteria checked
- Tests and commands run
- Screenshots or raw benchmark artifacts when applicable
- Any changed assumptions, limitations, or follow-up issues
